# Implementation Plan: Teams Interface

**Branch**: `006-teams-interface` | **Date**: 2026-07-25 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/006-teams-interface/spec.md`

## Summary

Replace the Teams placeholder page with a full-featured Teams interface. Add server-side paginated team listing, team cards with academy branding, Team Details modal with ordered roster, Create Team and Edit Team forms with 7–15 player roster selection, drag-and-drop plus keyboard-accessible roster reordering, atomic team+roster create/edit via `POST`/`PUT /api/v1/teams`, optimistic concurrency with version numbers, inactive player handling in roster display, and role-based authorization. Both frontend and backend work required.

## Technical Context

**Language/Version**: Python 3.12+ (backend), TypeScript 5.x (frontend)

**Primary Dependencies**: FastAPI, SQLAlchemy (async), Pydantic v2 (backend); React 18+, Tailwind CSS 3.x, Vite (frontend)

**Storage**: PostgreSQL (Docker-hosted), Alembic migrations

**Testing**: pytest + pytest-asyncio (backend unit), vitest + React Testing Library (frontend unit), Playwright (E2E)

**Target Platform**: Linux server (backend), modern browsers (frontend: Chrome, Firefox, Safari, Edge)

**Project Type**: Web application (FastAPI REST API + React SPA)

**Performance Goals**: Team list page (12 cards) loads in under 2 seconds; team creation (15 players) completes in under 3 minutes from form open

**Constraints**: WCAG 2.1 AA accessibility; responsive 320px–2560px; no hardcoded pixel values; optimistic concurrency via version_number

**Scale/Scope**: Academy-scale (tens of teams, hundreds of players); 5 user stories, 46 functional requirements
